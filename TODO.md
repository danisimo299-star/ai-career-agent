- **Interview Simulator** (`/dashboard/interview`) — a genuinely adaptive mock interview: one question at a time, evaluated (7-criteria breakdown, live feedback, occasional AI-offered follow-up capped at depth 1) before the next question is generated from the full transcript so far. Ends in a full report: overall + 5-category scores, strongest/weak areas (ranked by per-skill average, never the same skill in both lists), recommended next steps, and a question-by-question review with a real but non-authoritative "one strong approach" note per answer (never claimed as the only correct one). History + real progress stats (best/average/latest/count). Dashboard card shows real completed-count/last-score/next-step. A weak-technical-skill recommendation is surfaced on the report page (average < 60 across ≥2 questions) — a recommendation only, never an automatic roadmap edit. `AICareerService`'s old one-shot `generateInterviewQuestions` was replaced with three focused methods (`generateInterviewQuestion`, `evaluateInterviewAnswer`, `generateInterviewReport`) to support this. - **Job Matching** (`/dashboard/jobs`) — real vacancy search, filters (profession/city/format/experience/employment/salary/internship), and sorting, backed by a deterministic rule-based matching engine (`lib/career/job-matching.ts`) that scores skills/experience/location/career-goal/salary — never an LLM guess. HH.ru's public API was live-tested before building anything: `GET /vacancies` returns 403 without a registered OAuth app (which this deployment doesn't have), while `/areas` and `/dictionaries` are genuinely open — `HH_ACCESS_TOKEN` (optional) turns on real search once a token exists; without it, `HhJobsProvider` returns no results (never fabricated ones) and every vacancy — mock or real — always links out through a real, correctly-parameterized `hh.ru/search/vacancy` URL, using verified real area IDs and dictionary vocabulary. AI is used only twice, both narrating results the deterministic engine already computed: the AI Job Search Assistant (free text → Zod-validated structured filters, never a direct query) and "Prepare for this job" (resume recommendations, HR/technical questions, a prep plan — trusts the engine's matched/missing skills as ground truth). "Prepare for Interview" starts a real, vacancy-specific Interview Simulator session (the setup form's role picker now accepts a one-off custom role, not just the fixed catalog). Saved Jobs and the Application Tracker are one model (`SavedJob`, a 6-status enum) since the brief describes the same progression for both; status changes are always user-driven, never inferred. Career Score only ever produces a positive-framing note on a strong match, never a filter or gate.
