# Мобильный «Мой план»

Ветка: `feat/mobile-my-plan`.

## Поведение

- `/dashboard/plan` открывает «Сегодня»: активные задания, текущий этап, серия дней. Закрытые задания за сегодня и прежняя недельная история доступны в раскрываемых блоках.
- `/dashboard/plan?view=all` открывает «Весь план»: прежние этапы, задачи, ресурсы и действия.
- Цель и общий прогресс видны в обоих режимах. Оценка карьеры, срок, поиск вакансий, смена цели и пересоздание доступны в «Параметрах плана».
- `/dashboard/missions` и `/dashboard/roadmap` перенаправляют на соответствующий режим. Query-параметры, включая повторяющиеся, сохраняются; `view` задаётся исходным разделом.
- В мобильной и настольной навигации один пункт «Мой план». Ссылки из главной страницы, уведомлений и чата ведут в новый раздел.

## Сохранность данных

Схема Prisma, миграции, репозитории и API заданий/дорожной карты не изменены. Используются существующие записи и идентификаторы, связи с задачами и этапами, статусы, даты и ресурсы. Открытие экрана не запускает генерацию; штатное истечение срока вчерашних заданий сохранено.

Выполнение задания использует прежний сервис, который завершает связанную задачу плана. После успешной записи обновляются серверные данные и общий прогресс. При ошибке отметка задачи откатывается; повторные нажатия блокируются на время сохранения. Штатное пересоздание плана по-прежнему требует подтверждения и заменяет текущую карту — это действие пользователя, а не часть объединения разделов.

## Мобильная вёрстка

Сохранены палитра, шрифты, карточки и оформление ProfyMind. Шапка лендинга и основные CTA перестраиваются на узких экранах. Мобильные кнопки, поля, пункты меню и вкладки имеют высоту минимум 44 px; ввод — 16 px. Панели занимают ширину телефона, длинный текст и кнопки переносятся, учтены безопасные отступы. Ограничена ширина скелетонов загрузки. Глобального скрытия горизонтального переполнения нет.

## Проверка

Выполнено 8 тестов Playwright: Chromium и WebKit с эмуляцией iPhone. Проверены ширины 320, 390, 768 и 1440 px, лендинг и регистрация, вход, старые адреса, параметры URL, история, сохранность записей и ресурсов, начало/завершение/пропуск задания, ошибка запроса и повтор, обновление связанной задачи и прогресса, отметка/снятие отметки, перезагрузка, создание плана и заданий.

Тесты используют только временных пользователей в локальной PostgreSQL; они удаляются в `finally`. AI и вакансии работают через mock-провайдеры. Физические устройства, экранная клавиатура и внешние AI-провайдеры этим прогоном не проверяются.

Повторный запуск (с установленной схемой в локальной БД и `.env`):

```sh
npx playwright install chromium webkit
npm run test:e2e
npx tsc --noEmit
npx eslint src tests playwright.config.ts
npx next build
```

Playwright поднимает сервер на порту 3100 с mock-провайдерами. Если порт уже занят, используйте только запущенный с такими же настройками тестовый сервер. Трассы ошибок и скриншоты сохраняются в `test-results/` (не коммитятся). `next build` проверяет сборку без запуска миграций, в отличие от `npm run build`.
